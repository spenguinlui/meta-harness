你的 AI agent
該怎麼設計？

meta-harness 是一位住在 Claude Code 裡的顧問，專門幫你設計 AI agent 系統，也會動手實作。 它記得 13 個設計時該想清楚的面向，陪你把工具設計好、蓋出來。
改 prompt 是調字句，設計 harness 是調整模型周圍的整套系統。

從哪裡開始

六張卡片，從第一次開 session 到每個設計面向的細節。卡住的話，用上面的搜尋框過濾。

入門
  • 這是什麼？為什麼是顧問，不是產目錄骨架的工具？
  • 需要什麼：裝好 Claude Code CLI，心裡有個想設計的專案
  • 三行裝起來：git clone → cd → claude
  • 開 session 第一件事，用 /model 切到最強的 model
  • 不需要 .env，不需要 API key
5 個主題 → 新手入口
顧問的四種模式
  • /design <專案>：設計新的，或打掉重來
  • /healthcheck <專案>：拿 13 個面向做一次體檢
  • /retro <專案>：跑一陣子之後回頭檢視
  • /document <專案>：產中英雙語說明書
  • 不打指令、直接講白話也可以，顧問角色會自動載入
4 種模式 入口
13 個設計面向
  • 工具執行 · 上下文管理 · 記憶 · 規劃 · 執行迴圈
  • 權限與安全 · hook · 成效評估 · 可觀測性
  • 多 agent 協作 · 觸發時機 · 人的介面
  • 自我驗證覆蓋率（第 13 個）
  • 每一個都有很多選項，不是開關，而且彼此牽連
13 個面向 → 索引
設計流程的六個步驟
  • 1　需求訪談，10 到 20 分鐘，問五件事
  • 2　顧問自己寫設計方案，你不用做事
  • 3　你看過、給意見，來回改到定案
  • 4　分階段把檔案寫進你的專案
  • 4.5　自我驗證：非互動跑至少三次加上跑分
  • 5　驗收　·　6　幾週後回頭檢視
6 步 + 自我驗證 → 判斷邏輯
R-1 到 R-12：12 條基本規則
  • R-1 CLAUDE.md 不超過 50 行 · R-3 每個 hook 不超過 100 行
  • R-4 找不到就說找不到，不用流暢的猜測填補
  • R-6 不用沒解釋過的專有名詞和縮寫
  • R-8 自家層的問題自家層修 · R-9 框架層不碰任務內容
  • R-10 機器驗得了的產出，交付前先自己驗過
  • R-11 給別人用的東西一定要附說明書 · R-12 寫進專案的檔案要能獨立看懂
12 條，部分由 hook 強制 → 詳解
兩種人，還有會產出什麼
  • 設計者是設計這個工具的人，使用者是每天用它的人
  • sessions/：訪談紀要
  • prescriptions/：顧問寫的設計方案
  • experiments/<專案>/runs/：自我驗證的原始證據
  • BACKLOG.md：還沒處理的缺口
  • 實際內容全部在 .gitignore 裡，fork 出去不會互相污染
6 個落點 留檔
沒找到對應主題。換個關鍵字試試，或直接到 GitHub 翻原始碼。
