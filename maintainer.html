六張卡片：架構地圖、三個擴充入口、軸 13 自驗閘門、治理紀律與設計依據。

架構概覽 / Architecture
  • 身分層：.claude/skills/consultant/（建築師人格 + 6 步流程）+ document/ 雙語說明書
  • 知識層：13 設計軸 + R-1~R-12 + lessons
  • 前門層：.claude/commands/ 三 slash command + .claude/hooks/ 強制規則
  • 自驗層：experiments/meta-harness-eval/（13 scorer / 216 check / 100% coverage）
  • 不是 framework — 是「顧問身分 + pattern library + 對話流程」
4 層 → 細節
加設計軸 / Add Design Axis
  • 建 docs/design-axes/<n>-<name>.md（決策選項 + 耦合 + 反模式 + 案例）
  • 在 docs/design-axes.md 索引加一條
  • 升標題的軸數，更新 healthcheck.md 引用
  • 正交檢查：別跟現有 13 軸重疊（如 7 vs 11、9 vs 12 邊界已劃清）
  • 跑 run-self-verify.sh 確認全綠（軸數 drift 會被抓）
5 步 擴充
加 R-N / Universal Rule
  • 在 docs/universal-care-rules.md 加 ## R-N
  • 判準：離開這個 target / 這個人還成立嗎？跨 target 才入 universal
  • commit message 必答「為什麼不能刪源頭」（R-7：fix root cause，不固化壞流程）
  • 未通過跨 target 驗證 → 先落 docs/lessons.md（洞察，非強制規則）
  • 自驗會跑 test-universal-care-rules-schema.sh 驗 R-N 編號連續
4 步 + R-7 自問 → R-1~R-12
加模式 / Add Skill
  • 建 .claude/skills/<name>/SKILL.md（frontmatter name / description 必填）
  • 在 consultant skill 觸發表加一列
  • 必要時掛進 6 步流程（如 Step 5.5 / Step 6）
  • 加 .claude/commands/<name>.md 前門
  • 仿 document skill 的結構與雙語自驗循環
  • scorer：test-skill-spec-format.sh 抓 frontmatter / 引用對齊
5 步 擴充
軸 13 自驗閘門 / Self-verify
  • bash experiments/meta-harness-eval/run-self-verify.sh → 必 13/13 全綠
  • Stop hook 會擋住 session 結束（drift 修掉才放行）
  • 13 支 scorer 涵蓋 cross-references / prescription / target coverage / 設計軸 doc / healthcheck 一致性 / SKILL frontmatter / R-N schema / Stop hook 行為 / runner 完整性 / slash command 流 / consultant 核心 vocab / coverage.json schema
  • 寫新 scorer 用四 Pattern 之一：A 真實來源 + drift / B 觸發 + 斷言 / C scorer + METRICS / D 快照 + diff
  • dog food 三層閉環：atdd-task 自驗 ← meta-harness 規定自己也得自驗 ← CONTRIBUTING（鞋匠的孩子有鞋穿，是工程事實）
13 scorer · 216 check → 軸 13
治理四條 / Governance
  • R-7：不固化壞流程、fix 先 root cause（疊蓋症狀 = 規則膨脹陷阱）
  • R-8：不跨層越權（method-level 規則別寫進 target-specific 文件）
  • R-9：framework vs 任務內容分流
  • R-12：target 落地檔 self-contained（對 meta-harness 自身不適用——R-N / 設計軸是這裡的 ubiquitous language）
  • 顧問而非腳手架：13 軸耦合、沒對誰都剛好的標準模板
  • 規則分層：通則（R-N）/ 流程（consultant-flow）/ 格式（template）/ 反模式 分開放
4 條 + 設計哲學 → 詳解
沒找到對應主題——試試別的關鍵字，或 直接看 source。

動手前的 checklist
